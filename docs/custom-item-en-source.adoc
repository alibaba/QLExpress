=== Lexing rules for multi-character symbolic operators

When a custom operator consists of symbolic characters (e.g. `**`, `?.`, `*-`), the lexer matches by **longest registered prefix** rather than greedily merging every adjacent operator-like character. Only sequences that have been registered via `addOperator`, `addOperatorBiFunction`, etc. are combined into a single OPID token; everything else falls back to single-character tokens.

This ensures expressions such as `10*-1`, `5+-3`, and `a/-b` — a binary operator immediately followed by a unary prefix — are correctly parsed as `10 * (-1)`, `5 + (-3)`, and `a / (-b)` without requiring whitespace in between.

== Notes and recommendations

- Under the QLFunctionalVarargs calling convention, when invoking an extension function the first actual argument is the receiver object, followed by the call arguments; functions and operators do not include a receiver.
- Set the precedence of custom operators according to the intended expression semantics to avoid confusion with existing rules.
- Annotation-based registration only processes public methods, and duplicate names will fail to register; the batch registration result contains both success and failure lists.
